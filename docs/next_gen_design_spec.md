# RIN: PIT ARK 仕様書 v0.3

## 1. 企画概要

- ジャンル: `SFローグライト・ブロック崩し`
- 開発基準: `16ビット世代ゲーム機（スーパーファミコン相当）の表現制約・手触りを前提に設計する`
- 1ラン目標時間: `30分`
- 難易度方針: `モード分割（Story / Standard / Hardcore）`
- 初回選択: `Fusion Protocol` / `Reflex Protocol`

## 1.1 難易度モード

### Story（やさしい）

- 対象: 初見〜中級
- 初期ライフ: `+1`
- 敵HP倍率: `0.85`
- ドロップ倍率: `1.25`
- スコア倍率: `x0.9`
- 救済:
  - ライフ0時に1回だけ復活
  - 開始6分までは被弾軽減

### Standard（標準）

- 対象: 通常プレイ
- 初期ライフ: `基準`
- 敵HP倍率: `1.0`
- ドロップ倍率: `1.0`
- スコア倍率: `x1.0`

### Hardcore（高難度）

- 対象: 上級者
- 初期ライフ: `-1`
- 敵HP倍率: `1.25`
- ドロップ倍率: `0.9`
- スコア倍率: `x1.35`
- 制約:
  - 復活なし
  - 救済効果なし

数値ソース: `docs/tables/difficulty_modes.csv`

## 2. コア体験

- 破壊の快感: 反射と連鎖で敵・ブロックを処理する。
- 上達実感: プレイヤースキルとビルド理解の両方が伸びる。
- 構築の楽しさ: ラン内ビルド + ラン外拠点成長。

## 3. 30分進行設計（共通）

1. フェーズ1（0:00-6:00）: 導入、基本システム開示、最初の中ボス
2. フェーズ2（6:00-12:00）: ビルド分岐開始、敵属性追加
3. フェーズ3（12:00-18:00）: 密度上昇、リスク報酬イベント
4. フェーズ4（18:00-24:00）: 高難度波状戦、準ボス連戦
5. フェーズ5（24:00-30:00）: 最終ボス（3フェーズ）

## 4. プロトコル選択（ラン開始時）

### 4.1 Fusion Protocol（合成重視）

- 目的: ビルド爆発で敵を制圧
- 特徴:
  - アイテム出現率: `高`
  - ボール合成素材ドロップ: `高`
  - 反射判定補正: `標準`
  - 敵HP: `+10%`
  - スコア倍率: `x1.0`

### 4.2 Reflex Protocol（反射重視）

- 目的: 反射精度と角度管理で突破
- 特徴:
  - アイテム出現率: `低`
  - ボール合成素材ドロップ: `低`
  - 反射判定補正: `厳しめ`
  - 敵HP: `-10%`
  - 反射コンボ倍率: `高`
  - スコア倍率: `x1.2`

数値ソース: `docs/tables/protocol_profiles.csv`

## 5. SF世界観設定（実装最低限）

- 舞台: 崩壊軌道都市 `PIT ARK`
- プレイヤー: 反射兵装を持つ保守AIオペレーター
- 敵:
  - Drone（雑魚）
  - Shield Node（硬い）
  - Splitter（分裂）
  - Null Core（ボス）
- ブロック属性:
  - Alloy（通常）
  - Plasma（高反応）
  - Void（特殊効果）

## 6. システム仕様

### 6.1 ボール

- 最大同時数: `5`
- 基本速度: 定数固定（アイテム効果のみ増減）
- 種類:
  - Normal
  - Pierce（貫通）
  - Split（分裂）
  - Magnet（吸引）

### 6.2 アイテム

- W: バー拡張
- S: 低速化
- M: 追加ボール
- F: 高速化（ステージ2以降）
- 同一アイテム重複:
  - レベル上昇（上限3）
  - 効果時間 `+10秒`

数値ソース: `docs/tables/item_effects.csv`

### 6.3 スコア/評価

- 基本点: 敵・ブロック撃破
- 連鎖補正: コンボ時間内連続破壊で上昇
- 終了評価:
  - Time
  - Max Combo
  - Damage Taken
  - Cleared Phase

### 6.4 拠点成長（ラン外）

- 通貨: Core Shard
- 恒久強化（初期10種）:
  - 初期ライフ
  - 初期ドロップ率
  - 初期バー幅
  - Protocol固有パッシブ

## 9. 実装方針（アーキテクチャ）

### 9.1 方針

- ベース: `Layered + DDD-lite`（Pyxel向け軽量）
- 目的:
  - 機能追加時の変更範囲を限定
  - テスト可能なロジックを分離
  - 描画依存を境界に押し込む

### 9.2 レイヤ構成

- `game/domain`
  - エンティティ、値オブジェクト、ルール
  - 例: Ball、Effect、DifficultySettings
- `game/usecase`
  - 1フレーム進行、報酬適用、ステージ遷移
- `game/infra`
  - Pyxel入出力、保存、アセット読込
- `game/presentation`
  - HUD、メニュー、演出

### 9.3 現構成からの移行方針

- `game/systems.py` を段階分割:
  - BallSystem -> domain/usecase
  - StageField -> domain/usecase
  - EffectSystem -> domain/usecase
- `game/app.py` は
  - 入力受付
  - usecase呼び出し
  - 描画委譲
  のみを担当

### 9.4 テスト方針

- `domain/usecase`: 純ロジック単体テスト
- `infra`: 最小限（保存、パス、フォント読込）
- 回帰防止:
  - ライフ/速度/ドロップ率/難易度の固定ケース
  - プロトコル別の期待値テスト

## 10. 画像アセット方針（実現可否）

### 10.1 結論

- 実装可能。Pyxelでも十分運用できる。
- ただし「読みやすさ優先の解像度管理」が必須。

### 10.2 運用ルール

- スプライトサイズ:
  - 8x8 / 16x16 を基本
- 画像配置:
  - `assets/sprites/`
  - `assets/ui/`
  - `assets/backgrounds/`
- 命名:
  - `enemy_drone_idle_01.png`
  - `ui_panel_start_160x72.png`
- パレット:
  - 16色ルールを固定（逸脱禁止）

### 10.3 描画最適化

- 背景は低頻度再描画
- 動的要素のみ毎フレーム更新
- エフェクトは「短時間・少数」制限

### 10.4 制作フロー

1. ラフを 240x180 前提で作成
2. 8x8 グリッドへスナップ
3. パレット監査
4. 実機確認（可読性・点滅）
5. 反映
